## Тест #2: Race condition detection (опционально - 10 минут)

Если хотите проверить более сложный кейс, создайте тестовый файл:

### Создать файл test-race.kt:

```kotlin
package ru.chtcholeg.test

class TestRepository {
    private val cache = mutableMapOf<String, String>()

    suspend fun getData(key: String): String {
        return cache.getOrPut(key) {
            // Simulate API call
            delay(100)
            "data-$key"
        }
    }
}
```

### Закоммитить:
```bash
git checkout -b test-race
git add test-race.kt
git commit -m "Test: race condition"
```

### В AI Agent:
```
/review-pr test-race
```

### Ожидаемый результат:
```
**Файл:** test-race.kt:X-Y
**Severity:** 🔴 Critical
**Проблема:** Shared mutable state без синхронизации

**Текущий код:**
```kotlin
private val cache = mutableMapOf<String, String>()

suspend fun getData(key: String): String {
    return cache.getOrPut(key) { ... }
}
```

**Как проявится:**
Две корутины вызывают getData("same-key") параллельно:
1. Обе проверяют cache["same-key"] → null
2. Обе входят в getOrPut блок
3. HashMap может быть corrupted → ConcurrentModificationException

**Рекомендация:**
```kotlin
private val cache = mutableMapOf<String, String>()
private val mutex = Mutex()

suspend fun getData(key: String) = mutex.withLock {
    cache.getOrPut(key) { "data-$key" }
}
```
```
