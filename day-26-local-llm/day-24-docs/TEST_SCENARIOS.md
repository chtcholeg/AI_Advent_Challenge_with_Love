# Team Assistant - Test Scenarios

Сценарии тестирования Team Assistant для проверки всех возможностей.

## Сценарий 1: Базовые операции с задачами

### 1.1. Просмотр всех задач

**Запрос:**
```
/task list
```

**Ожидаемый результат:**
- Список всех 12 задач из tasks.json
- Группировка по статусам или в табличном виде
- Показаны: ID, название, статус, приоритет, исполнитель

**Проверка:**
- ✅ Все задачи отображаются
- ✅ Информация корректна
- ✅ Форматирование читабельное

### 1.2. Фильтрация задач

**Запрос 1:** Открытые задачи
```
/task list status=open
```

**Ожидаемый результат:** 6 задач со статусом "open"

**Запрос 2:** Высокий приоритет
```
/task list priority=high
```

**Ожидаемый результат:** Задачи с приоритетом "high" (task_001, task_002, task_005, task_006)

**Запрос 3:** Задачи конкретного разработчика
```
/task list assignee=developer1
```

**Ожидаемый результат:** Задачи developer1 (task_001, task_003, task_005, task_006, task_009)

**Запрос 4:** Комбинированный фильтр
```
/task list status=open priority=high
```

**Ожидаемый результат:** Открытые задачи с высоким приоритетом

### 1.3. Детали конкретной задачи

**Запрос:**
```
/task task_005
```

**Ожидаемый результат:**
- Полная информация о task_005
- Название, описание, статус, приоритет
- Исполнитель, метки, дедлайн
- Time tracking (8/24 hours)
- Git ветка: feature/pm-server
- Даты создания/обновления

**Проверка:**
- ✅ Вся информация отображается
- ✅ Форматирование структурированное
- ✅ Git интеграция работает (если есть)

## Сценарий 3: AI-анализ приоритетов

**⚠️ Требует:** GigaChat credentials

### 3.1. Полный анализ приоритетов

**Запрос:**
```
/task priorities
```

**Ожидаемый результат:**

**Summary:**
- Общий анализ ситуации с приоритетами
- Выявление проблем (critical task просрочена, blocked tasks)

**Recommendations:**
- Минимум 2-3 рекомендации
- Формат: task_id, current → suggested, reason, urgency_score
- Пример: task_012 critical → URGENT (просрочена)

**Execution Order:**
- Оптимальная последовательность выполнения задач
- Учёт зависимостей и приоритетов

**Risks:**
- Выявленные риски по задачам
- Способы снижения рисков

**Insights:**
- 2-3 инсайта для улучшения планирования
- Например: переоценка задач, перераспределение нагрузки

**Проверка:**
- ✅ AI анализ выполнен (не ошибка "AI disabled")
- ✅ Рекомендации конкретные с task_id
- ✅ Обоснования логичны
- ✅ Формат JSON корректно распарсен

### 3.2. Анализ при создании задачи

**Запрос:**
```
/task create Добавить поддержку темной темы в UI
```

**Ожидаемый результат:**

**Шаг 1:** AI анализ (`suggest_priority`)
- Suggested priority: high или medium
- Confidence score: 0.7-0.9
- Reasoning: почему этот приоритет
- Estimated hours: 8-16
- Suggested labels: ["feature", "ui"]

**Шаг 2:** Создание задачи
- Task ID: task_013 (новый)
- Применены AI рекомендации

**Шаг 3:** Результат
- Показана созданная задача
- Объяснение выбора параметров

**Проверка:**
- ✅ AI анализ выполнен
- ✅ Задача создана с рекомендованными параметрами
- ✅ Объяснение понятное

## Сценарий 4: Интеграция с Git

- Активные ветки
- Связь с задачами (если есть git_branch в tasks)

**Проверка:**
- ✅ Git инструменты использованы
- ✅ Коммиты показаны
- ✅ Связь с задачами отображена

### 4.2. Git информация для задачи

**Запрос:**
```
/task task_005
```

**Ожидаемый результат:**
- Git ветка: feature/pm-server
- Если есть коммиты - их список
- История изменений ветки (через git_log)
- Diff ветки (опционально)

**Проверка:**
- ✅ Git ветка показана
- ✅ git_log вызван для ветки
- ✅ Информация о коммитах корректна

## Сценарий 5: Интеграция с RAG

**⚠️ Требует:** RAG включен, индекс создан

### 5.1. Контекст проекта в ответах

**Запрос:**
```
/task create Оптимизировать работу с embeddings в индексации
```

**Ожидаемый результат:**
- AI учитывает контекст из документации
- Упоминает существующие компоненты (EmbeddingService, DocumentIndexer)
- Предлагает приоритет с учётом архитектуры
- Метки соответствуют проекту

**Проверка:**
- ✅ RAG контекст использован
- ✅ Рекомендации учитывают архитектуру
- ✅ Упоминания конкретных компонентов

### 5.2. Вопросы о проекте

**Запрос:**
```
/task Какие задачи связаны с RAG?
```

**Ожидаемый результат:**
- Поиск задач с label "rag" или упоминанием RAG
- Контекст из документации о RAG
- Связь с существующей функциональностью

**Проверка:**
- ✅ Задачи найдены корректно
- ✅ RAG контекст добавлен
- ✅ Ответ информативный

## Сценарий 6: Произвольные запросы

### 6.1. Заблокированные задачи

**Запрос:**
```
/task Какие задачи заблокированы и почему?
```

**Ожидаемый результат:**
- Список задач со статусом "blocked"
- task_009 (баг с настройками)
- Объяснение причины блокировки (из description или анализа)
- Рекомендации по разблокировке

**Проверка:**
- ✅ Найдена task_009
- ✅ Объяснение логичное
- ✅ Рекомендации даны

### 6.2. Просроченные задачи

**Запрос:**
```
/task Какие задачи просрочены?
```

**Ожидаемый результат:**
- Список задач с due_date < current date
- Минимум task_012 (если current date > 2026-02-20)
- Дни просрочки
- Рекомендации по действиям

**Проверка:**
- ✅ Просроченные задачи найдены
- ✅ Расчёт дней просрочки
- ✅ Приоритизация предложена

### 6.3. Загруженность разработчика

**Запрос:**
```
/task Сколько задач у developer1?
```

**Ожидаемый результат:**
- Количество задач
- Распределение по статусам
- Estimated vs spent hours
- Load score
- Рекомендация по новым задачам

**Проверка:**
- ✅ Подсчёт корректен
- ✅ Детализация показана
- ✅ Анализ загрузки дан

### 6.4. Следующая задача для работы

**Запрос:**
```
/task Какую задачу мне взять следующей?
```

**Ожидаемый результат:**
- Анализ открытых задач
- Учёт приоритетов
- Учёт зависимостей (blocked by)
- Учёт дедлайнов
- Конкретная рекомендация с обоснованием

**Проверка:**
- ✅ Анализ выполнен
- ✅ Рекомендация конкретная (task_id)
- ✅ Обоснование логичное

## Сценарий 7: Обработка ошибок

### 7.1. Несуществующая задача

**Запрос:**
```
/task task_999
```

**Ожидаемый результат:**
- Сообщение "Task not found"
- Предложение использовать /task list

**Проверка:**
- ✅ Ошибка обработана корректно
- ✅ Полезное сообщение

### 7.2. AI недоступен

**Условие:** Не настроены GigaChat credentials

**Запрос:**
```
/task priorities
```

**Ожидаемый результат:**
- Сообщение "AI analysis is disabled"
- Инструкция по настройке credentials

**Проверка:**
- ✅ Graceful degradation
- ✅ Понятное сообщение об ошибке

### 7.3. PM Server недоступен

**Условие:** PM Server не запущен

**Запрос:**
```
/task list
```

**Ожидаемый результат:**
- Сообщение об ошибке подключения
- Инструкция проверить сервер

**Проверка:**
- ✅ Ошибка обработана
- ✅ Подсказка для решения
