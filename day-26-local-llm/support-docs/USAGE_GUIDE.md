# User Support Assistant - Usage Guide

Руководство по использованию ассистента технической поддержки (Day 23).

## Быстрый старт

После завершения setup (см. `SETUP_GUIDE.md`):

1. Запустите AI Agent:
```bash
./gradlew :ai-agent:run
```

2. Убедитесь, что:
   - ✅ RAG enabled (индекс загружен)
   - ✅ CRM MCP Server connected
   - ✅ System Prompt установлен

3. Начните задавать вопросы!

## Примеры использования

### 1. Простые вопросы из FAQ

#### Вопрос о проблеме
```
Пользователь: Почему не работает авторизация?
```

**Что происходит:**
1. AI Agent использует RAG для поиска в `authentication.md`
2. Находит раздел про проблемы авторизации
3. Предоставляет пошаговое решение

**Ответ агента:**
```
Проблема с авторизацией обычно связана с креденшелами GigaChat API.

Вот что нужно проверить:

1. Проверьте креденшелы в `local.properties`:
   gigachat.clientId=...
   gigachat.clientSecret=...

2. Пересоберите проект:
   ./gradlew clean build

3. Убедитесь, что токен не истек

Подробнее в документации: support-docs/faq/authentication.md
```

#### Вопрос об установке
```
Пользователь: Как установить приложение на Android?
```

**Ответ из RAG:**
```
Для установки Android версии:

1. Подключите устройство или запустите эмулятор

2. Выполните команду:
   ./gradlew :chat:installDebug

Требования:
- Android 7.0 (API 24) или выше
- 2 GB RAM минимум

Подробнее: support-docs/faq/installation.md
```

### 2. Вопросы с контекстом пользователя

#### Информация о пользователе
```
Пользователь: Расскажи про пользователя user_001
```

**Что происходит:**
1. AI Agent вызывает MCP tool `get_user`
2. Получает информацию из CRM

**Ответ:**
```
Информация о пользователе:

ID: user_001
Имя: Иван Петров
Email: ivan.petrov@example.com
План подписки: Pro
Дата регистрации: 2024-01-15
Последняя активность: 2026-02-14
Статус: active
```

#### История тикетов
```
Пользователь: Какие проблемы были у user_001?
```

**Что происходит:**
1. AI Agent вызывает `get_user_tickets`
2. Получает список тикетов с деталями

**Ответ:**
```
История тикетов пользователя Иван Петров (user_001):

1. Тикет #ticket_001 [open]
   Тема: Не работает авторизация
   Описание: При попытке войти получаю ошибку 'Invalid credentials'
   Приоритет: high
   Создан: 2026-02-14T10:30:00Z

2. Тикет #ticket_005 [open]
   Тема: Приложение работает медленно
   Описание: После обновления заметно медленнее загружается список сессий
   Приоритет: medium
   Создан: 2026-02-14T09:45:00Z

Всего открытых тикетов: 2
```

### 3. Комбинированные запросы (RAG + MCP)

#### Персонализированный ответ
```
Пользователь: У user_001 проблема с авторизацией. Помоги решить.
```

**Что происходит:**
1. Получает тикет через MCP: `get_user_tickets`
2. Находит решение через RAG в `authentication.md`
3. Комбинирует информацию

**Ответ:**
```
Привет, Иван Петров!

Вижу ваш тикет #ticket_001 про проблему авторизации.

Вы на тарифе Pro, так что все функции доступны.

Согласно вашему описанию, вы получаете ошибку "Invalid credentials".

Вот решение:

1. Проверьте креденшелы в local.properties:
   gigachat.clientId=...
   gigachat.clientSecret=...

2. После изменения выполните:
   ./gradlew clean build

3. Убедитесь, что токен не истек на сайте GigaChat

Кстати, у вас есть еще открытый тикет #ticket_005 про медленную работу.
Хотите, я помогу и с этим? 😊

Я обновлю статус тикета #ticket_001 после решения проблемы.
```

### 4. Поиск тикетов

#### По ключевому слову
```
Пользователь: Найди все тикеты про MCP серверы
```

**Что происходит:**
AI Agent вызывает `search_tickets` с query "MCP"

**Ответ:**
```
Найдено тикетов про MCP серверы: 1

1. Тикет #ticket_003 [resolved]
   Пользователь: Алексей Козлов (alex.kozlov@example.com)
   Тема: MCP сервер не отвечает
   Описание: Запустил Git MCP сервер, но AI Agent не может подключиться
   Приоритет: high
   Создан: 2026-02-12

   Решение: Проблема была в firewall. Пользователь изменил порт на 8081.
   Решен: 2026-02-13
```

#### По категории и статусу
```
Пользователь: Покажи открытые тикеты с высоким приоритетом
```

**Что происходит:**
AI Agent вызывает `list_tickets` с фильтрами `status: "open", priority: "high"`

**Ответ:**
```
Открытые тикеты с высоким приоритетом:

1. ticket_001: Не работает авторизация [open] (high priority)
   Пользователь: user_001 - Иван Петров
   Создан: 2026-02-14T10:30:00Z
```

### 5. Обновление тикетов

#### Отметить как решенный
```
Пользователь: Отметь ticket_001 как решенный. Пользователь обновил креденшелы и всё заработало.
```

**Что происходит:**
AI Agent вызывает `update_ticket_status`

**Ответ:**
```
✅ Тикет обновлен!

ID: ticket_001
Статус: open → resolved
Обновлен: 2026-02-14T12:30:00Z
Решение: Пользователь обновил креденшелы и всё заработало

Отлично, что проблема решена! 🎉
```

#### Добавить заметки
```
Пользователь: Добавь заметку к ticket_002: попросил пользователя обновить JDK до версии 17
```

**Что происходит:**
AI Agent вызывает `update_ticket_status` с параметром `notes`

**Ответ:**
```
✅ Заметка добавлена к тикету ticket_002

Заметка: Попросил пользователя обновить JDK до версии 17
Обновлен: 2026-02-14T12:35:00Z
```

### 6. Сложные сценарии

#### Анализ повторяющихся проблем
```
Пользователь: Какие проблемы встречаются чаще всего?
```

**Что происходит:**
1. AI Agent вызывает `list_tickets` без фильтров
2. Анализирует категории и темы
3. Группирует по типам проблем

**Ответ:**
```
Анализ тикетов:

Топ-3 категории проблем:
1. Authentication (28%) - 2 тикета
   - Invalid credentials
   - Token expired

2. Features (28%) - 2 тикета
   - Настройка RAG
   - Telegram напоминания

3. Performance (14%) - 1 тикет
   - Медленная работа приложения

Рекомендации:
- Добавить в FAQ раздел про частые ошибки авторизации
- Создать quick start guide для RAG
- Оптимизировать загрузку сессий
```

#### Статистика по пользователям
```
Пользователь: Какие пользователи наиболее активны?
```

**Что происходит:**
1. `list_users` для получения всех пользователей
2. `list_tickets` для подсчета тикетов на пользователя

**Ответ:**
```
Статистика активности:

Топ пользователи по количеству тикетов:
1. user_001 (Иван Петров) - 2 тикета
   План: Pro
   Статус: active

2. user_002 (Мария Сидорова) - 2 тикета
   План: Basic
   Статус: active

3. user_005 (Дмитрий Волков) - 1 тикет
   План: Basic
   Статус: inactive

Обратите внимание:
- user_005 неактивен с 2026-02-01
- Возможно, стоит проверить его последний тикет
```

## Best Practices

### Для пользователей (техподдержка)

1. **Указывайте user ID или ticket ID**
   ```
   ✅ "Проблема у user_001"
   ✅ "Обнови статус ticket_003"
   ❌ "У пользователя проблема" (без ID)
   ```

2. **Будьте конкретны в запросах**
   ```
   ✅ "Найди тикеты про авторизацию"
   ✅ "Открытые тикеты с высоким приоритетом"
   ❌ "Покажи что-то важное"
   ```

3. **Используйте естественный язык**
   ```
   ✅ "У Ивана проблема с MCP. Что делать?"
   ✅ "Помоги user_002 настроить RAG"
   ❌ get_user_tickets(user_id="user_001") (не надо так)
   ```

### Для администраторов

1. **Регулярно обновляйте FAQ**
   - Добавляйте новые решения
   - Обновляйте устаревшую информацию
   - Переиндексируйте после изменений

2. **Мониторьте качество ответов**
   - Проверяйте, что RAG находит правильные документы
   - Убеждайтесь, что MCP данные актуальны
   - Собирайте feedback от пользователей

3. **Используйте метрики**
   - Время решения тикета
   - Процент решенных с первого раза
   - Частота использования RAG vs MCP

## Ограничения

### Текущие ограничения

1. **JSON-based CRM**
   - Нет транзакций
   - Нет concurrent updates
   - Не подходит для production

2. **Нет аутентификации**
   - Любой может читать/изменять тикеты
   - Нужно добавить для production

3. **Нет истории изменений**
   - Не сохраняется, кто и когда изменил тикет
   - Нет audit log

### Как улучшить для production

См. `SETUP_GUIDE.md` раздел "Production Deployment"

## Команды быстрого доступа

### Запуск
```bash
# AI Agent
./gradlew :ai-agent:run

# CRM MCP Server (если не автозапуск)
cd mcp-servers/crm && ./START.sh
```

### Индексирование
```bash
# Переиндексировать FAQ
./gradlew :shared:runIndexing --args="index ./support-docs/faq ./support-index.json md"

# Проверить статистику
./gradlew :shared:runIndexing --args="stats ./support-index.json"

# Тестовый поиск
./gradlew :shared:runIndexing --args="search ./support-index.json 'авторизация' 5"
```

### Проверка данных
```bash
# Пользователи
cat mcp-servers/crm/data/users.json | jq

# Тикеты
cat mcp-servers/crm/data/tickets.json | jq

# Открытые тикеты
cat mcp-servers/crm/data/tickets.json | jq '[.[] | select(.status == "open")]'
```
