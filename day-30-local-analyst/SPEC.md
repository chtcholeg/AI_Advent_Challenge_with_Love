# Спецификация: Local Log Analyst

> Дата интервью: 2026-02-23
> Статус: черновик, одобрен к реализации

---

## 1. Обзор продукта

Локальное веб-приложение для анализа логов с помощью локальной LLM (Ollama).
Пользователь загружает файл с логами, приложение автоматически понимает структуру, и далее можно задавать вопросы на естественном языке: «Какая ошибка встречается чаще всего?», «Где теряются пользователи?», «Какова средняя оценка?».

Всё работает **полностью локально** — данные не покидают машину.

---

## 2. Целевая аудитория

**Смешанная**: технические специалисты (разработчики, DevOps) и нетехнические (менеджеры, аналитики).
UI должен быть понятен без знания SQL или форматов логов.

---

## 3. Поддерживаемые форматы входных данных

| Формат | Примечания |
|--------|-----------|
| SQLite (`.db`, `.sqlite`) | Нативная поддержка через sqlite3 |
| CSV | Автодетект разделителя, кодировки (UTF-8, Windows-1251 и др.) |
| JSON / JSON Lines | Плоские объекты и массивы |
| Plain text (`.log`, `.txt`) | Построчный парсинг с извлечением структуры через LLM |

**Безопасность по типам файлов**: разрешены только `.db`, `.sqlite`, `.csv`, `.json`, `.jsonl`, `.log`, `.txt`.
**Максимальный размер загрузки**: 1 GB (настраивается в конфиге).

## 5. LLM-интеграция (Ollama)

### 5.1 Конфигурация

- Модель: **задаётся пользователем** в настройках (поле ввода)
- URL по умолчанию: `http://localhost:11434`
- При старте backend **проверяет доступность** `GET /api/tags` — если Ollama не отвечает, показывает уведомление и инструкцию по запуску

### 5.2 Стратегии работы с данными для LLM

**Маленькие файлы (< 10 MB)**
→ Данные загружаются в SQLite in-memory
→ LLM получает: схему + 10-20 примеров строк + вопрос пользователя
→ LLM генерирует SQL-запрос
→ Backend выполняет SQL, результат возвращается в LLM для текстового объяснения

**Большие файлы (10–500 MB)**
→ Комбинированный подход:
- Для **структурированных данных** (CSV, SQLite): LLM генерирует SQL, backend выполняет локально
- Для **свободного текста** (log, txt): chunking → каждый чанк суммаризируется → итоговая суммаризация

**Лимит памяти**: pandas загружает chunked через `chunksize`, не целиком.

### 5.3 Обработка ошибок LLM

1. Backend валидирует SQL (regex/parse-check: нет DROP/DELETE/UPDATE/INSERT)
2. Если SQL невалиден — **2 автоматических retry** с уточнённым промптом
3. Если после 2 попыток всё ещё ошибка — возвращается пользователю с объяснением и предложением перефразировать вопрос
4. Логирование всех неудачных запросов для отладки

### 5.4 SQL Sandbox

Разрешены только `SELECT`-запросы.
Запрещено: `DROP`, `DELETE`, `UPDATE`, `INSERT`, `CREATE`, `ALTER`, `ATTACH`, `PRAGMA` (деструктивные).

### 5.5 Детектирование схемы

1. Backend анализирует заголовки, типы данных, примеры значений
2. LLM предлагает интерпретацию полей (например: `ts` → `timestamp`, `lvl` → `severity`)
3. Пользователю показывается таблица со схемой для **подтверждения или редактирования**
4. Одобренная схема сохраняется в SQLite и используется в последующих запросах

## 6. Пользовательский интерфейс

### 6.1 Основной поток

```
[Загрузка файла(ов)] → [Автодетект схемы → подтверждение] → [Анализ / чат]
```

### 6.2 Зона анализа (гибрид)

**Быстрые действия** (preset-кнопки, зависят от типа лога):
- «Самые частые ошибки»
- «Временной паттерн активности»
- «Аномалии»
- «Топ-10 значений [поле]»
- «Средняя / медианная [числовое поле]»

**Чат**: свободный ввод вопроса на естественном языке (русский / английский / любой)

### 6.3 Вывод результатов

| Тип | Реализация |
|-----|-----------|
| Текст | Markdown-рендер с кодом |
| Таблица | Интерактивная таблица с сортировкой |
| График | LLM возвращает `{ type, data, labels }` → Recharts рендерит |
| Код (SQL) | Сворачиваемый блок с подсветкой синтаксиса |

### 6.4 UX при долгом ответе

- **Progress stages**: `Парсинг` → `Агрегация` → `Запрос LLM` → `Готово`
- **Streaming**: текст LLM появляется побуквенно через SSE (Server-Sent Events)
- Кнопка «Остановить» всегда доступна

### 6.5 Несколько файлов в сессии

- Можно загрузить несколько файлов разных форматов в одну сессию
- Каждый файл — отдельная «таблица» в рабочем пространстве
- Вопросы можно задавать по конкретному файлу или по всем сразу («сравни ошибки из двух файлов»)

## 7. Персистентность

| Данные | Хранилище |
|--------|-----------|
| История диалогов | SQLite (локальная БД приложения) |
| Одобренные схемы файлов | SQLite |
| Загруженные файлы | Временная директория (`/tmp/log-analyst/`) |
| Настройки (модель, URL Ollama) | SQLite или `.env` |

История чата сохраняется между сессиями (закрытие браузера не удаляет её).

## 8. Экспорт отчётов

| Формат | Содержимое |
|--------|-----------|
| **Markdown** | Текст ответов + таблицы + описание схемы |
| **PDF** | Аналог Markdown + встроенные графики (через weasyprint или puppeteer) |
| **JSON** | Сырые данные агрегаций, структурировано |
| **CSV** | Табличные результаты запросов |

Экспорт доступен как для одного ответа, так и для всей сессии.

---

## 9. Многоязычность логов

- Логи на любом языке поддерживаются нативно — LLM обрабатывает их без предварительной нормализации
- LLM отвечает **на языке вопроса пользователя**
- Системные промпты на английском для максимальной совместимости с моделями

---

## 10. Безопасность

| Мера | Реализация |
|------|-----------|
| Фильтрация типов файлов | Whitelist расширений + проверка MIME-типа |
| Лимит размера | Настраиваемый в `.env` (по умолчанию 1 GB) |
| SQL sandbox | Только SELECT, проверка через sqlparse |
| Кодировка | chardet/charset-normalizer для автодетекта |
| Без аутентификации | Приложение для localhost, один пользователь |

---

## 11. Обработка граничных случаев

| Кейс | Поведение |
|------|----------|
| Неоднородная кодировка (UTF-8 + cp1251) | chardet на каждый чанк, репорт пользователю о проблемных строках |
| LLM галлюцинирует / уверен но неправ | Показывать сгенерированный SQL рядом с ответом — пользователь может его проверить |
| OOM при большом файле | Streaming-чтение через pandas chunksize, лимит на in-memory данные |
| Ollama недоступен | Автопроверка при старте, graceful degradation с понятным сообщением |
| Пустой файл / несовместимая структура | Ранняя валидация с диагностическим сообщением |
| Невалидный JSON | Попытка парсинга как JSON Lines, потом как plain text |

## 14. Решения по открытым вопросам

| Вопрос | Решение |
|--------|---------|
| PDF-библиотека | **weasyprint** (pure Python, графики как base64 PNG) |
| SQL в истории | Показывать SQL рядом с ответом (сворачиваемый блок) + кнопка «Редактировать и запустить» |
| Кэш SQL-запросов | **Да** — кэш в SQLite (ключ: hash(file_id + sql)), инвалидация при новой загрузке файла |
