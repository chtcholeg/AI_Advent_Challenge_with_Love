# JuriLytics — Plan

## Что делаем

Приложение анализирует юридические документы (договоры, ToS, оферты) и объясняет их на человеческом языке.
Языковая модель: **GigaChat** (Sber).

## Фаза 1: Прототип (CLI)

### Цель
Проверить, насколько хорошо GigaChat справляется с анализом юридических текстов.
Быстро запустить, легко тестировать.

### Запуск
```bash
python analyze.py contract.txt
```

### Стек
- Python 3.11+
- `gigachat` — официальный SDK от Sber
- `pdfplumber` — парсинг PDF (если нужен)
- `argparse` или `typer` — CLI-аргументы
- `rich` — красивый вывод в терминале (опционально)

### Поток работы
```
1. Читаем файл по пути из аргумента
2. Извлекаем текст (txt / pdf)
3. Формируем prompt
4. Отправляем в GigaChat
5. Выводим структурированный результат
```

### Структура вывода
```
📋 КРАТКОЕ СОДЕРЖАНИЕ
  [2-3 предложения о сути документа]

⚠️  ОПАСНЫЕ ПУНКТЫ
  1. [пункт X] — [почему опасен]
  2. ...

📌 НА ЧТО ОБРАТИТЬ ВНИМАНИЕ
  - [важные условия, сроки, штрафы]

❓ ВОПРОСЫ, КОТОРЫЕ СТОИТ ЗАДАТЬ
  - [что непонятно или подозрительно]
```

### Промпт (черновик)
```
Ты юридический помощник. Проанализируй договор ниже.

Твой ответ должен содержать строго 4 раздела:
1. Краткое содержание (2-3 предложения)
2. Опасные пункты (список с объяснением почему опасны)
3. На что обратить внимание (сроки, штрафы, ограничения)
4. Вопросы, которые стоит задать другой стороне

Отвечай на русском языке. Пиши просто и понятно, без юридического жаргона.

ДОГОВОР:
{text}
```

### Структура файлов прототипа
```
prototype/
  analyze.py        # точка входа
  gigachat_client.py  # обёртка над GigaChat SDK
  file_reader.py    # чтение txt/pdf

  .env              # GIGACHAT_AUTHORIZATION_KEY=...
  requirements.txt
  sample_contract.txt  # тестовый документ
```

## Открытые вопросы с вариантами решения

### Q1: Форматы файлов в прототипе
**Варианты:**
- A) Только `.txt` — минимум сложности, достаточно для теста качества
- B) `.txt` + `.pdf` — чуть больше работы, но реалистичнее

**Рекомендация:** Начать с A, добавить PDF во второй итерации прототипа.

---

### Q2: Многотурный диалог в прототипе
**Варианты:**
- A) Только одноразовый анализ — запустил, получил результат, вышел
- B) После анализа входим в Q&A режим: можно задавать вопросы по документу

**Рекомендация:** Реализовать B — это ключевое для проверки качества GigaChat.
Пример:
```
> Анализ завершён. Задайте вопрос по документу (или 'выход'):
> что будет если я не заплачу вовремя?
```

---

### Q3: Обработка длинных документов
Проблема: GigaChat имеет лимит контекста (~32k токенов для GigaChat-Pro).
Длинный договор может не поместиться.

**Варианты:**
- A) Просто обрезать текст до лимита — быстро, но теряем часть документа
- B) Разбить на чанки, анализировать каждый отдельно, объединить результаты
- C) Сначала сделать краткое извлечение ключевых пунктов, потом анализировать

**Рекомендация:** A для прототипа (добавить предупреждение если файл большой), B/C для полного приложения.
