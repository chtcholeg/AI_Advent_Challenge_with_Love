# Support Assistant - Руководство по использованию

## Обзор

Support Assistant — это специализированный режим AI Agent для технической поддержки пользователей GigaChat Multiplatform Chat App.

**Возможности:**
- ✅ Доступ к базе знаний через RAG (FAQ, документация)
- ✅ Интеграция с CRM через MCP инструменты (тикеты, пользователи)
- ✅ Персонализированная поддержка на основе контекста пользователя
- ✅ Обновление статусов тикетов
- ✅ Дружелюбное и профессиональное общение

## Способы запуска

### 1. Команда `/support` (рекомендуется)

Самый простой способ активации Support Assistant:

```
/support Почему не работает авторизация?
```

Или просто:

```
/support
```

При запуске без аргументов выведется приветствие и готовность помочь.

**Преимущества:**
- Автоматическая загрузка специализированного промпта
- Полный доступ ко всем инструментам (MCP + Local + RAG)
- Контекст поддержки уже настроен

### 2. Через Task Tool (для субагентов)

```
[Использовать Task tool с типом "support-assistant"]
```

**Когда использовать:**
- Для фоновой обработки тикетов
- Для делегирования задач поддержки субагенту
- Для изолированного выполнения с ограниченными инструментами

## Workflow поддержки

Support Assistant следует следующему workflow:

### 1. Идентификация пользователя
```
get_user userId=user_123
get_user_tickets userId=user_123
```

### 2. Поиск решения
```
[RAG поиск]: "ошибка авторизации"
search_tickets query="авторизация"
```

### 3. Персонализированный ответ

Учитывает:
- Тарифный план пользователя
- История тикетов
- Предыдущие решения
- Контекст из базы знаний

### 4. Обновление тикета
```
update_ticket_status ticketId=ticket_001 status=resolved notes="..."
```

## Примеры использования

### Пример 1: Простой вопрос

**Вход:**
```
/support Как запустить AI Agent?
```

**Что произойдёт:**
1. Загрузится промпт Support Assistant
2. RAG найдёт инструкции в FAQ/документации
3. Ответ будет с конкретными командами и примерами

### Пример 2: Проблема пользователя с контекстом

**Вход:**
```
/support userId=user_123 Проблема с авторизацией
```

**Что произойдёт:**
1. Получит информацию о пользователе через CRM
2. Проверит историю тикетов
3. Найдёт решение в RAG
4. Даст персонализированный ответ с учетом тарифного плана
5. Обновит статус тикета

### Пример 3: Поиск похожих проблем

**Вход:**
```
/support Есть ли у кого-то проблемы с MCP серверами?
```

**Что произойдёт:**
1. `search_tickets query="MCP сервер"`
2. Анализ похожих тикетов
3. Обобщение решений
4. Рекомендации на основе успешных кейсов

## Доступные инструменты

### CRM Tools (через MCP)
- `get_user` — информация о пользователе
- `get_user_tickets` — все тикеты пользователя
- `get_ticket` — детали конкретного тикета
- `search_tickets` — поиск тикетов по ключевому слову
- `update_ticket_status` — обновление статуса тикета

### RAG Tools
- `rag_search` — поиск в базе знаний (FAQ, docs)

### Local Tools
- `read` — чтение файлов проекта
- `grep` — поиск в коде
- `glob` — поиск файлов
- `bash` — выполнение команд (для тестирования решений)
- `ask_user_question` — уточнение деталей у пользователя

## Настройка окружения

### 1. Подготовка базы знаний (RAG)

Проиндексируйте FAQ и документацию:

```bash
export GIGACHAT_CLIENT_ID="..."
export GIGACHAT_CLIENT_SECRET="..."

./gradlew :shared:runIndexing --args="index ./support-docs/faq ./support-knowledge.json md txt"
```

### 2. Настройка MCP сервера (CRM)

Убедитесь, что CRM MCP сервер запущен и настроен в AI Agent:

```bash
cd mcp-servers
python -m crm.main
```

### 3. Настройка AI Agent

В Settings → RAG:
- Enable RAG: ✅
- Index Path: `./support-knowledge.json`
- Top K: 5

В Settings → MCP:
- Добавьте CRM server (stdio, python -m crm.main)

## Метрики и качество

Support Assistant отслеживает:
- ✅ Время первого ответа
- ✅ Количество решенных тикетов с первого раза
- ✅ Использование базы знаний (RAG hits)
- ✅ Персонализация (использование CRM контекста)

## Troubleshooting

### Проблема: Support Assistant не находит промпт

**Решение:**
Убедитесь, что файл существует:
```
support-docs/config/support-assistant-prompt.md
```

### Проблема: CRM инструменты недоступны

**Решение:**
1. Проверьте, что CRM MCP server запущен
2. Проверьте настройки MCP в AI Agent
3. Перезапустите AI Agent

### Проблема: RAG не находит информацию

**Решение:**
1. Проверьте, что индекс создан: `./support-knowledge.json`
2. Проверьте настройки RAG в Settings
3. Переиндексируйте документы

## Расширение возможностей

### Добавление новых FAQ

1. Создайте `.md` файл в `support-docs/faq/`
2. Переиндексируйте базу знаний
3. RAG автоматически найдёт новую информацию

### Кастомизация промпта

Отредактируйте файл:
```
support-docs/config/support-assistant-prompt.md
```

Промпт перезагружается при каждом вызове `/support`.

### Добавление новых CRM инструментов

Расширьте MCP сервер в `mcp-servers/crm/`:
1. Добавьте новый инструмент в `main.py`
2. Перезапустите MCP server
3. Support Assistant получит доступ автоматически

## Best Practices

1. **Всегда проверяйте контекст пользователя** через CRM перед ответом
2. **Используйте RAG** для поиска актуальной информации
3. **Структурируйте ответы** — шаги, примеры, альтернативы
4. **Будьте эмпатичны** — пользователь обратился с проблемой
5. **Обновляйте тикеты** — отслеживайте прогресс
6. **Эскалируйте** сложные проблемы — не все можно решить сразу
