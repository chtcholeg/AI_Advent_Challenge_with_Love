# Test Scenarios - User Support Assistant

Тестовые сценарии для проверки работы ассистента технической поддержки (Day 23).

## Предварительные требования

Перед запуском тестов убедитесь, что:
- ✅ FAQ проиндексированы: `support-index.json` существует
- ✅ CRM MCP Server запущен
- ✅ AI Agent запущен с правильным System Prompt
- ✅ RAG enabled в настройках
- ✅ MCP CRM подключен в настройках

## Сценарий 1: Простой вопрос из FAQ

### Цель
Проверить, что RAG правильно находит информацию в документации.

### Шаги

1. **Вопрос:**
   ```
   Почему не работает авторизация?
   ```

2. **Ожидаемый результат:**
   - Агент использует RAG для поиска в `authentication.md`
   - Предоставляет пошаговое решение:
     - Проверить `local.properties`
     - Выполнить `./gradlew clean build`
     - Проверить срок действия токена

3. **Проверка:**
   - ✅ Ответ содержит конкретные шаги
   - ✅ Упоминается файл `local.properties`
   - ✅ Есть команда `./gradlew clean build`
   - ✅ Есть ссылка на документацию

### Ожидаемый ответ (пример)

```
Проблема с авторизацией обычно связана с креденшелами GigaChat API.

Решение:

1. Проверьте креденшелы в `local.properties`:
   gigachat.clientId=YOUR_CLIENT_ID
   gigachat.clientSecret=YOUR_CLIENT_SECRET

2. Пересоберите проект:
   ./gradlew clean build

3. Убедитесь, что токен не истек на сайте GigaChat API

Подробнее: support-docs/faq/authentication.md
```

## Troubleshooting тестов

Если тесты не проходят:

1. **RAG не находит информацию:**
   ```bash
   # Проверьте индекс
   ./gradlew :shared:runIndexing --args="stats ./support-index.json"

   # Переиндексируйте
   ./gradlew :shared:runIndexing --args="index ./support-docs/faq ./support-index.json md"
   ```

2. **MCP не отвечает:**
   ```bash
   # Проверьте статус
   ps aux | grep "crm.main"

   # Перезапустите
   cd mcp-servers/crm && ./START.sh
   ```

3. **Агент не использует инструменты:**
   - Проверьте System Prompt
   - Убедитесь, что MCP enabled в Settings
   - Перезапустите AI Agent
