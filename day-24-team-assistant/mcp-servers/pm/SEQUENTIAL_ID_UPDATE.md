# Sequential ID Update для PM MCP Server

## Обзор изменений

Добавлена поддержка сквозной нумерации задач с хранением последнего ID в метаданных файла.

## Что изменилось

### 1. Новый формат файла tasks.json

**Было (старый формат - простой список):**
```json
[
  { "id": "task_001", ... },
  { "id": "task_002", ... }
]
```

**Стало (новый формат с метаданными):**
```json
{
  "metadata": {
    "last_task_id": 14
  },
  "tasks": [
    { "id": "task_001", ... },
    { "id": "task_002", ... }
  ]
}
```

### 2. Улучшенная генерация ID

**Было:**
- ID генерировался на основе количества задач (`len(tasks) + 1`)
- При удалении задач могли возникать коллизии ID
- Требовался перебор существующих ID для поиска свободного

**Стало:**
- ID генерируется на основе сквозного счётчика в метаданных
- Счётчик всегда увеличивается, никогда не уменьшается
- Гарантированная уникальность ID без перебора

### 3. Обратная совместимость

Код поддерживает **оба формата**:
- Старый формат (простой список) автоматически конвертируется при загрузке
- При сохранении всегда используется новый формат с метаданными
- Миграция данных происходит прозрачно для пользователя

## Функциональность изменения статуса

**Изменение статуса уже было реализовано** через инструмент `update_task`.

### Доступные статусы:
- `open` - Новая задача
- `in_progress` - В работе
- `review` - На ревью
- `done` - Завершена
- `blocked` - Заблокирована
- `cancelled` - Отменена

### Доступные приоритеты:
- `low` - Низкий
- `medium` - Средний
- `high` - Высокий
- `critical` - Критический

### Пример изменения статуса:

```bash
curl -X POST http://localhost:8012/message \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": "1",
    "method": "tools/call",
    "params": {
      "name": "update_task",
      "arguments": {
        "task_id": "task_013",
        "status": "in_progress",
        "priority": "high",
        "assignee": "developer1",
        "spent_hours": 4
      }
    }
  }'
```

## Миграция существующих данных

### Автоматическая миграция

Используйте скрипт `migrate_tasks.py`:

```bash
cd mcp-servers
python3 pm/migrate_tasks.py
```

Скрипт:
1. Создаёт резервную копию `tasks.json.backup`
2. Анализирует существующие задачи
3. Определяет максимальный ID из существующих задач
4. Конвертирует в новый формат с метаданными

### Пример вывода:

```
Migrating tasks.json...
Created backup: /path/to/pm/data/tasks.json.backup
Migration complete!
  Tasks: 12
  Last task ID: 12
```

## Использование в AI Agent

### Команда /task

```
/task create Добавить новую фичу
```

Агент автоматически:
1. Создаст задачу с новым ID (например, task_015)
2. Проанализирует приоритет через AI (если включено)
3. Вернёт информацию о созданной задаче

### Изменение статуса

```
/task Измени статус task_013 на done
```

Агент:
1. Найдёт задачу task_013
2. Обновит статус через update_task
3. Подтвердит изменение

## Преимущества

1. **Сквозная нумерация** - ID никогда не повторяются
2. **Простота** - минимальные изменения в коде
3. **Обратная совместимость** - поддержка старого формата
4. **Надёжность** - счётчик хранится в файле, не теряется
5. **Гибкость** - легко изменить статус, приоритет, любые поля задачи
